# 暖薪 Warmwage

> 你的薪水，真的算對了嗎？——依台灣《勞動基準法》幫勞工試算實領薪資、加班費與請假扣款的 App。

## App 簡介

許多上班族、輪班族、兼職打工族和按件計酬的工作者（例如按摩師）看不懂自己的薪資單：加班費有沒有少給？請一天假為什麼全勤被扣光？勞健保是不是扣太多？

暖薪依《勞動基準法》、《勞工請假規則》與官方最新費率表，把底薪、津貼、加班、請假、勞健保、勞退、二代健保與所得稅逐項算出來，讓勞工每個月都能自己對帳。

- 不用註冊帳號、沒有伺服器、沒有廣告與追蹤
- 所有資料只加密存在使用者自己的手機
- 支援 iPhone、Android 與網頁版

## 主要功能

| 類別 | 功能 |
|---|---|
| 薪資試算 | 月薪／時薪／按件計酬；勞保、健保、勞退依官方分級表自動配對；二代健保補充保費、所得稅、職工福利金 |
| 加班與排班 | 平日、休息日、國定假日、例假日加班費依法定倍率計算；跨日大夜班以 00:00 切分；畫筆式排班月曆；排休者一週只休一天時，第 6 個上班日自動依休息日計算 |
| 請假與特休 | 14 種假別票卡（法定額度、已請、剩餘）；全勤獎金依 2026 年新版勞工請假規則按比例扣減；特休年資與未休工資結算 |
| 勞基法照妖鏡 | 連續出勤、單日超時、月加班超過 46 小時、全勤多扣等即時警示，附法條與罰則 |
| 多份工作 | 兼職族可建立多份工作各自算薪，大盤顯示全部合計 |
| 公務人員 | 身份可切換為公務人員：本俸、加給與自訂薪資項目（逐項設定是否計稅、是否計入健保、破月是否按日）；公保依生效日期的費率（非年金、全額年金、基本年金或自訂）自動代扣；健保依俸給總額；退撫依本俸 × 2 × 提撥率，支援退撫基金與個人專戶制（含自願增提），自繳不計稅；不適用的勞基法功能自動隱藏 |
| 破月計算 | 月中到職或離職的月份按日精算：公務人員依俸給法 ÷ 當月日數，勞工依勞動契約選 ÷30 或 ÷ 當月日數；勞保、就保、勞退每月以 30 日計，健保依月底是否在保；大盤顯示「在職 N 天」並附算式 |
| 按件計酬 | 沒有底薪、做一位客人算一位的工作（例如按摩）：建立價目表（按時間或按次），每天在月曆記錄客人，金額不固定的額外獎金也能當天自行輸入；受僱者依勞基法換算平日每小時工資額、檢查最低工資、計算有薪假，承攬者試算執行業務所得扣繳與二代健保；指定率達標時指定客另有加給（可依客數或時數計算） |
| 即時計數器 | 大盤上的「今天已經賺了」：依排班每秒累積，顯示每分鐘、每小時與這一班的金額；休息時間自動暫停，跨午夜的大夜班也算得對 |
| 鎖定畫面小工具 | iOS WidgetKit 小工具（長方形、圓形、單行、主畫面小方塊）：不用打開 App 就看得到今天賺了多少，上班中每分鐘更新；預設手機鎖著時遮蔽金額，認出本人才顯示，使用者可改成一律顯示 |
| 公司加班費率 | 公司給的倍率比勞基法好時（例如平日 ×1.5、×2），每種加班的每一段都能自訂；計算一律取「自訂與法定較高者」，填得比勞基法低時提示並以法定計算 |
| 自訂計薪週期 | 公司從每月 26 日（或其他日期）起算時，排班工時、加班、請假扣薪、全勤、伙食出勤依計薪期間計算；勞健保與勞退仍按月、獎金依發放日；大盤與 PDF 標出起訖日 |
| 彈性時薪 | 時薪＋每小時加給（每月可不同）、指定日加給、期間達標獎金（例如期間出勤獎金、久任獎勵金）、單日工時獎金（逐級累加或只取最高一級，依公司規範選擇） |
| 太空助理 | 主畫面右下角懸浮的太空人（助理名稱與頭像由主題決定，招財貓主題是「招財助理」）：用自己的話發問，完全離線比對 27 則常見問題與 21 則法規說明；回答一字不改地引用並附出處、法規依據與「前往設定頁」按鈕；問得太籠統時列出選項讓使用者選，不在範圍內時說明原因並提供 1955 專線等正式管道，不硬湊答案 |
| 資料安全 | 本機加密儲存、Face ID／指紋鎖、AES-256-GCM 加密備份檔 |
| 介面 | 霧面科技風、16 款主題（含 Premium 插畫主題「太空外星人」「日系招財貓」，各有專屬背景、導覽圖示、薪資卡片裝飾與助理；主題引擎讓新主題只需覆寫和預設不同的設定）、深色模式、大字體、懸浮毛玻璃導覽列、「薪資津貼設定」精簡成一頁選單（每項一列附摘要，點進去才看到完整設定）、12 步功能導覽（涵蓋彈性時薪、按件計酬、每日額外獎金、太空助理）；iPhone 數字鍵盤上方的「完成」列；看其他月份時點頂部月份文字一鍵回到本月（附「回本月」提示、觸覺回饋與 VoiceOver 標籤）；系統設定內建「常見問題」（6 類 27 題，可搜尋） |
| Premium | PDF 薪資單與 CSV 對帳報表、完整法條說明、12 款限定主題（含太空外星人、日系招財貓）、無限歷史月份、彈性時薪、指定率加給 |

## 技術架構

### Flutter 跨平台
- 一套 Flutter（Dart）程式碼同時產出 iOS、Android 與網頁版
- 四個主分頁＋懸浮毛玻璃導覽列；Material 3 主題系統擴充成 14 款漸層配色，每款都通過深淺色的 WCAG 對比檢查
- 動畫只在需要時播放：畫面靜止時不排程任何畫格，以節省電量

### 勞基法計算設計
- **計算核心與畫面分離**：所有法規計算集中在一個純 Dart 的模型層，不依賴任何 UI、網路或檔案，因此每條規則都能用單元測試驗證
- **每月一份帳本**：設定可「沿用到之後的月份，直到修改該月」，符合薪資每月可能調整的實際情況
- **依日期計算工資**：每一天可以有自己的每小時加給，加班費以「當天的平日每小時工資額」乘以倍率；達標獎金由排班、加班與請假紀錄即時推算，不另外存一份可能過期的結果
- **法規資料化、依年度集中**：勞健保費率與級距表、補充保費、扣繳率與起扣點、最低工資、國定假日，集中在單一的年度設定檔，計算時依「結算年度」取用，並註明官方資料來源；最低工資與國定假日可線上更新並加密快取
- **計算沒有副作用**：計算薪資不會修改設定物件（結算年度不同時用副本計算），畫面不會因為「算了一下別的月份」而改變
- **跨日班引擎**：以 00:00 為界切分每一段出勤，分別判斷平日、休息日、國定假日與例假日，再套用各自的倍率
- **按件計酬**：每筆服務紀錄建立時記下當時的單價，之後調整價目表不會改到已發生的薪資；受僱者的平日每小時工資額＝本月按件工資 ÷ 工作時數（勞基法施行細則第 31 條），用來計算加班費、有薪假與最低工資檢查；承攬者改用執行業務所得的扣繳與補充保費規則，並關閉勞基法警示

### 資料加密
- iPhone：系統 Keychain（AES-256）；Android：Keystore 保護的金鑰＋AES-GCM；網頁版：瀏覽器 WebCrypto
- 每個月份、每份工作分開加密儲存
- 加密備份檔：使用者自訂密碼，PBKDF2-HMAC-SHA256（31 萬次）導出金鑰＋AES-256-GCM；金鑰導出在背景執行緒進行，畫面不卡頓
- 正式版程式碼混淆、關閉除錯 log；依 OWASP MASVS 做過自我資安審視

### 資料安全與正確性
使用者的薪資紀錄只存在手機上，沒有伺服器可以幫忙救回，所以「絕不遺失、絕不覆蓋」是最高原則：
- **存檔格式版本與逐版遷移**：每筆存檔都有格式版本號，舊格式讀取時一版一版升級；遇到比 App 新的格式就停下來請使用者更新，不寫入任何資料。新增按件計酬時，內容雖然向下相容，仍把格式升到第 2 版，讓舊版 App 不會在看不懂服務紀錄的情況下把它覆蓋掉
- **損毀資料不覆蓋**：讀不出來時顯示說明畫面（重試、從加密備份還原、以空白資料重新開始），還原或重新開始前都先另存一份副本；單一月份損毀不影響其他月份
- **寫入中斷可復原**：存檔寫到一半當機，下次讀取仍能找回已寫入的月份
- **刪除重裝不默默顯示舊資料**：iOS 刪除 App 後 Keychain 會殘留。以 UserDefaults 的安裝標記判斷「升級」與「重裝」，分不出來時一律詢問使用者，絕不自動清除；iCloud 備份還原不會被誤判
- **錯誤不被吞掉**：存檔、備份、PDF、購買失敗時一定用中文說明並可重試；本機錯誤紀錄只記錯誤類型與程式位置（不記訊息內容，避免夾帶金額或姓名），使用者可自願匯出寄給開發者，不使用任何第三方錯誤回報 SDK

### App 內購買（1.0.3 起：RevenueCat）
- 月度、年度訂閱與終身買斷，由 **RevenueCat**（`purchases_flutter`）驗證與管理：匿名用戶模式（免註冊、免登入），以 `vip` 權限判斷會員；換手機或重裝後用同一個 Apple ID「恢復購買」
- 商店介面與 RevenueCat 完全分開：會員邏輯只認得自己定義的「權利快照」，RevenueCat 只出現在一個檔案裡，測試用假的商店模擬購買、取消、到期、退款、斷網與逾時
- **查不到 ≠ 沒有購買**：啟動先用本機存的狀態，之後才向商店確認；逾時、斷網、初始化失敗一律沿用；RevenueCat 主動通知「沒有權利」時先再確認一次才取消
- **舊會員搬家**：原生內購時期的購買紀錄，第一次開啟新版時同步給 RevenueCat 一次；同步成功前絕不取消會員
- **恢復購買**：一定在 20 秒內結束；查詢中顯示太空人漂浮動畫並禁止連點，結束後明確告知「已恢復／查無有效訂閱／請檢查網路」
- 價格、試用期與年繳折扣一律讀取商店；價格載入前購買按鈕鎖住；付費牆附 EULA 與隱私權政策連結；隱私標示、隱私清單與隱私權政策三者一致

### 鎖定畫面小工具（WidgetKit）
- App 把今天起 14 天的「每小時工資＋排班時段」寫進 App Group，只放計算需要的數字與班別名稱，不含公司名稱、底薪等資料
- 小工具自己依時間計算，時間軸預先排好上班中的每一分鐘（休息時間不排），App 不用開著；WidgetKit 不能每秒更新，所以鎖定畫面以每分鐘為單位
- 計算邏輯放在只依賴 Foundation 的 Swift 檔，能在 Mac 上直接編譯測試，與 App 端的 Dart 測試使用相同案例
- 隱私：金額預設 `privacySensitive()`，手機鎖著時由系統遮蔽

### 上線後營運監控（Supabase＋Discord）
使用者的薪資資料仍然只在手機上；後端只接收 RevenueCat 的訂閱事件（匿名 ID），用來掌握上線後的營運狀況：
- **即時訂閱通知**：RevenueCat Webhook → Supabase Edge Function（Deno）→ Discord，事件、取消原因、購買平台、方案全部翻成繁體中文；正向事件綠色、扣款異常橘色、取消與過期紅色。以 Authorization 驗證來源，比對採固定時間比較；Discord 發送失敗回 502 讓 RevenueCat 重送
- **每日 23:59 營運摘要**：pg_cron 呼叫 Edge Function，彙整今日實收（定價 ÷ 1.05 × 85%）、新訂閱、試用、續訂、取消、退款，與昨日比較；累積概況由 RevenueCat v2 唯讀 API 即時讀取（含 Webhook 接上之前的訂閱與試用）
- 事件存進開啟 RLS、沒有任何 policy 的資料表（只有後端讀得到），同一事件重送不會重複記錄；所有密碼、Webhook 網址與 API 金鑰只放在 Supabase 環境變數與 Vault，不進版本控制

## 開發中遇到的挑戰與解法

| 挑戰 | 解法 |

## 除錯實錄（節錄）

### 1. 「請假與法規」捲到底再捲回來，排班月曆變空白
- **重現**：第一次寫的測試竟然通過。檢查 `git status` 才發現工作目錄已有另一個背景工作改過的程式；改在 `git worktree` 建立的乾淨副本上重現，月曆標題仍是 11 月，格子卻顯示別的月份。
- **根本原因**：讀 `table_calendar` 原始碼，內部 PageView 沒有自己的 key，保存頁碼時與外層清單的 `PageStorageKey('leave')` 共用同一個欄位。月曆被回收重建時，把外層的捲動像素（例如 3000）當成「第 3000 頁」，跳到 2100 年以後。
- **修法**：月曆包在每次重建都全新的 `PageStorage` 裡，一律依目前月份顯示。不採用「讓月曆記住自己的頁碼」，因為月曆不在畫面上時仍可切換月份，會讀回舊月份；這個情況也寫成測試。
- **驗證**：修正前 3 項測試失敗、修正後全部通過；模擬器快速甩動 3 輪；golden 逐像素不變。

### 2. iPhone 數字鍵盤輸入完收不起來
- **根本原因**：iPhone 的數字鍵盤沒有「完成」鍵，Flutter 的輸入框在手機上點外面也不會失去焦點；Android 與網頁沒有這個問題。
- **修法**：在 `MaterialApp.builder` 加一層，iOS 鍵盤打開時在正上方顯示「完成」，並把這一列的高度加進 `viewInsets`，畫面會自動往上讓，不擋住輸入中的欄位；點空白處也能收起。全 App（含底部面板）一次生效。
- **測試**：以 `FakeViewPadding` 模擬鍵盤、`TargetPlatformVariant` 切換平台，驗證 iOS 顯示、Android 不顯示。

### 3. golden 圖在 Mac 通過、在 GitHub 的 Linux 失敗
- **調查**：下載 CI 上傳的差異圖，差異最多 0.11%，集中在斜向光澤紋路與裝飾小點的邊緣；兩邊 31 張的尺寸完全相同，代表排版一致。
- **決定**：不放寬誤差（會漏掉 1 像素的真實跑版），改為 Mac 與 Linux 各存一套基準圖，兩邊都逐像素比對；CI 提供手動按鈕在 Linux 產生新的基準圖。

### 4. 新增「點月份回到本月」時的三個小坑
- **測試說工具列溢位**：先用 `git stash` 拿掉自己的修改再跑，發現原本就溢位，原因是測試字型比真實字型寬。改為月份文字最寬 132、超過等比例縮小，測試改成「出現提示前後，箭頭與『⋯』大小完全相同」。
- **點完殘留一塊底色**：單元測試看不到，是模擬器截圖發現的。按鈕跳回本月後變成停用，還沒淡出的按壓水波留在畫面上；用 `KeyedSubtree(key: ValueKey(是否本月))` 讓按鈕在狀態切換時重建。
- **測試失敗、commit 卻照樣送出**：`flutter test | tail -1 && git commit` 的結束代碼來自 `tail`，永遠成功。補上修正 commit，並記下要用 `set -o pipefail` 或先存下結果再判斷。

### 5. 公務人員計薪：查證與「需求變了」的測試
- **費率生效期間寫錯**：第一版把 7.83% 當成 2024 年以前一直適用；寫測試前再查官方計算表，發現它是 113/1/1 起才實施。改成只套用 113 年，更早的月份標「待確認」。
- **前一階段的測試失敗了，但這是對的**：加入公保、退撫後，第 1 階段「保費為 0」的測試失敗。先手算新數字（例如退撫 50,000 × 2 × 15% × 35% = 5,250），和程式一致才更新預期值，並把算式寫進註解。
- **證明「只新增、不修改」**：用 `git diff` 確認特性測試基準 0 行刪除；第一次出現 2 行刪除，原因是產生器的輸出沒有格式化，統一格式後才是真正的 0 行。


### 6. 面板關不掉、常見問題的內容會過時
- **使用者回報**：服務紀錄記到第 3 筆後，面板長進動態島，拖曳橫槓看不到也拉不到。用 `FakeViewPadding` 模擬動態島重現，9 個面板加上 `useSafeArea` 修正，並以掃描原始碼的測試防止再犯。
- **常見問題**：寫內容時查證抓到「少算差額提醒其實是 Premium」「免費 3 個月只限制往前查看」兩處錯誤；回答提到的按鈕名稱與數字都寫成測試。
- **測試小坑**：`tester.pageBack()` 用英文「Back」找返回鍵，中文介面找不到，改成直接點 `BackButton`。

### 7. 太空人助理：測試都過，模擬器上卻捲不到最新的回答
- **症狀**：單元測試全部通過，但在 iPhone 模擬器截圖時，連續問到第三題，畫面還停在第一題的回答。
- **第一次判斷錯了**：以為是模擬器整合測試的限制，調整測試後依然失敗。
- **根本原因**：對話用 `ListView`，它只建立畫面附近的元件；最新的問題還沒建立，`GlobalKey` 拿不到位置，`ensureVisible` 什麼也沒做。單元測試的畫面較高，剛好都建立了，所以沒抓到。
- **修法與防範**：對話最多保留 40 則、全部建立，發問後把問題捲到畫面頂端；單元測試改成「iPhone SE、1.3 倍字、連問 6 題」，讓最新的問題一定在畫面外。
- **另外兩個小坑**：懸浮按鈕的進場動畫原本 0.9 秒，被既有的「所有進場動畫 0.6 秒內結束」測試擋下；一個「小螢幕溢位」的失敗，先換回一般主題跑對照組，發現一樣溢位，原來是測試把 iPhone SE 的像素密度設錯，不是程式的問題。

### 8. 「重複請求合併」寫錯一個箭頭，Future 永遠在等它自己
- **症狀**：加入「同一年的國定假日同時被要求多次只送一次」後，所有畫面測試都逾時。
- **調查**：先懷疑剛改的「測試改用 iOS 平台」，用對照組（拿掉 iOS 設定）排除；再寫探針測試印出畫面文字，看到行事曆一直是「同步中…」。
- **根本原因**：`whenComplete(() => _inFlight.remove(year))`——`remove` 會回傳這個 Future 本身，`whenComplete` 會等回呼回傳的 Future，於是自己等自己。
- **修法與防範**：回呼改成不回傳值的區塊，並寫測試確認「三個同時的請求只送一次、完成後可以再下載」。

### 9. 每日報表「抓不到試用」
- **症狀**：使用者說應該有兩位免費試用，日報卻顯示 0。
- **調查**：直接查資料表，發現沒有任何真實事件——Webhook 是當天晚上才接上，RevenueCat 不會補送接上之前發生的事件。
- **修法**：每日報表的「累積概況」改為呼叫 RevenueCat v2 API 即時讀取（試用中、有效訂閱、MRR）。金鑰只開唯讀權限，從後台建立後直接存進 Supabase，不經過對話與版本控制；用暫時的探測函式確認 API 欄位，用完即刪。

### 10. 小工具無法安裝到模擬器
- **症狀**：加入小工具後，模擬器安裝失敗：「Failed to create app extension placeholder」。
- **根本原因**：小工具的 Info.plist 用 `$(FLUTTER_BUILD_NAME)` 帶版本號，但小工具的建置設定沒有引用 Flutter 的 xcconfig，版本號是空的。
- **修法**：建置設定的基底改指向 `Flutter/Release.xcconfig`（Debug 用 `Debug.xcconfig`），小工具的版本號從此自動跟 App 一致。

## 測試方式

- **單元與畫面測試：1,330 項以上**，每次提交與部署前都必須全部通過；覆蓋率約 93%
  - 勞基法計算：加班倍率、請假扣薪、全勤比例扣減、勞健保級距、二代健保、所得稅、特休年資、跨日班
  - 彈性時薪：以使用者回饋的實際數字建立測試案例（例如時薪 210＋加給 40 的加班 1 小時應為 335、公司算法 321.4；上滿 12 小時的分級獎金逐級累加 1,700、取最高 800）
  - 按件計酬：以使用者回饋的價目建立案例（指壓 60 分鐘 $500、油壓 30 分鐘 $280、套餐按次計價；指定率 60% 達標時只有指定客每 30 分鐘 +$10，59% 不加給；依客數與依時數兩種算法；承攬 $30,000 扣繳 $3,000、補充保費 $633）
  - 畫面：7 種手機尺寸 × 1.0／1.3 倍字體捲到底不溢位；16 款主題 × 深淺色對比度（含薪資卡片文字、加減項金額）
  - 購買流程：付款成功、取消、處理中、掉單補發、恢復購買、兌換代碼（以模擬商店測試）
  - 備份：加密、解密、密碼錯誤、新舊格式相容
  - **畫面 golden test**：四個分頁整頁與主要彈窗共 31 張 × Mac／Linux 兩套，逐像素比對
  - **會員權利**：購買、續訂、到期、訂閱與終身方案退款、沒有網路、查詢逾時、查詢途中購買、恢復購買
  - **特性測試**：30 組代表性設定（月薪、時薪、按件計酬、各類加班、跨日班、國定假日、各假別、全勤、勞健保、所得稅、多份工作、公務人員、破月）共 112 筆，每個金額、警示代碼、每段加班金額都必須與基準完全相同，用來保護重構與每年的法規更新
  - **公務人員與破月**：以手算核對的完整範例建立測試（例如本俸 53,075 公保 D 7.22% 自付 1,341、退撫自繳 5,573；6/5 到職公保 F 按 26 ÷ 30 自付 2,629；勞工 6/5 到職勞保按 26 天）
  - **舊資料相容**：存檔格式已升到第 4 版；以第 1、2、4 版實際寫出的存檔與加密備份檔作為固定樣本，驗證讀取、讀取後再存檔、損毀與寫入中斷的情境，以及舊版 App 讀到新格式時會停下來
  - **錯誤情境**：以會失敗的假儲存、假商店模擬存檔失敗、檔案損壞、付款失敗，確認使用者看得到說明並能重試
  - **安裝狀態**：全新安裝、從舊版升級、刪除後重裝、iCloud 備份還原
- **小工具與後端測試**：小工具的計算邏輯以 Swift 在 Mac 上測試（上班中、休息、跨午夜大夜班、超出資料範圍、時間軸只排上班中的每一分鐘）；Edge Function 以 `deno test` 測試事件翻譯、顏色、金額、台灣時間換日、日報排版
- **模擬器整合測試**：在 iPhone 模擬器上以真實字型逐頁檢查版面並自動產生商店截圖
- **效能與耗電測試**：量測捲動時的畫格時間；確認每個分頁靜止後不再排程畫格；切換分頁、開關付費牆各 50 次的壓力測試
- **持續整合與部署**：每個分支與 PR 都在 GitHub Actions 跑靜態分析、全部測試（含 golden）與覆蓋率摘要；推送到主分支後通過才部署網頁版
- **實機手動測試清單**：刪除重裝、iCloud 還原、舊版升級等只能在實機確認的情境，每次送審前用 TestFlight 逐項驗證
